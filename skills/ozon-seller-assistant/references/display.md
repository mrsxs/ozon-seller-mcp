# 展示规范

## 按任务选择表格

| 场景 | 主表字段 | 摘要卡候选 | 口径提醒 |
|---|---|---|---|
| 商品 | 名称、货号、SKU、审核/归档状态 | 全店商品数、已查询数 | 总数与本次样本分开 |
| 价格 | 名称/货号、当前价格、划线价、最低价、币种 | 已查询商品数 | 不同币种不合计；最低价不保证最终成交价 |
| 库存 | 货号、仓库、方案、现有、预留、可用 | 已查记录数、可用库存为零数 | 标明按 SKU/仓库记录还是去重商品 |
| 货件 | 货件号、状态、件数、发运截止时间、仓库 | 已查货件数、状态分布 | 货件数不等于订单数 |
| 财务 | 日期、货件号、费用类型、金额、币种 | 同币种同口径合计 | 项目明细与货件总额避免重复累加 |
| 连通测试 | 查询项目、接口、HTTP 状态、耗时、结果 | 成功项目数、店铺币种 | 说明执行的是只读查询 |

数字右对齐并用千分位；金额统一小数位并注明币种。日期标注时区；标识符以文本保存。真实零显示 0，未知/不适用显示 — 并解释。状态显示中文，必要时附原枚举。

对于未核实阈值，不直接给库存贴“高风险”。可写“可用库存为 0”；用户给出低库存阈值后再据此筛选。

## ozon_render_report 参数

```json
{
  "filename": "ozon-inventory.html",
  "report": {
    "title": "Ozon 库存概览",
    "subtitle": "仓库与商品明细",
    "scope": "仅本次查询样本；不代表全店",
    "queried_at": "实际查询时间及其时区",
    "metrics": [
      {"label": "已查询记录", "value": 0, "unit": "条", "note": "由实际结果填入"}
    ],
    "sections": [
      {
        "title": "库存明细",
        "note": "按商品与仓库记录展示",
        "columns": [
          {"key": "offer_id", "label": "货号", "type": "text"},
          {"key": "warehouse", "label": "仓库", "type": "text"},
          {"key": "free_stock", "label": "可用库存", "type": "number"}
        ],
        "rows": []
      }
    ],
    "limitations": ["填写实际查询未覆盖的范围；没有限制可省略。"]
  }
}
```

上面是结构示例，不是待发布的数据。将数值和 rows 替换为已核实结果，不用示例零值制造报告。

列类型：`text`、`number`、`money`、`status`。`money` 列可追加 `currency: "CNY"`。数据 key 与 rows 对应；最多 8 张摘要卡、20 章节、每表 10000 行。只展示真实存在的字段，不凭空填补。

HTML 默认深蓝页头、浅色内容、蓝色操作按钮，表头固定，长表内部滚动。支持搜索、数值排序、CSV 导出、键盘操作、移动端和打印；页面不自动联网，无 JavaScript 时原始数据表仍可阅读。

不画无依据的销售趋势。确有跨日数据并需要图表时，可在有可靠本地图表工具的宿主生成额外图表；不能把当前报告渲染器不存在的能力说成已支持。
